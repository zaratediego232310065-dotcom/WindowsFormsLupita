Windows Forms en C#: del programa de consola a la ventana gráfica

Una guía pensada para primer semestre. Aquí aprenderás qué es una interfaz gráfica, cómo responde a lo que hace el usuario y cómo escribir tu primera aplicación de escritorio sin frustrarte.

Dificultad: básicaLectura: 15 minutosRequisito: variables y métodos

1. ¿Qué es Windows Forms?

Hasta ahora tus programas vivían en una terminal: pedías datos con Console.ReadLine() y mostrabas resultados con Console.WriteLine(). Windows Forms (WinForms) es la biblioteca de .NET para crear aplicaciones de escritorio con ventanas, botones, cajas de texto y menús.

Consola

Flujo lineal

El código corre de arriba hacia abajo. El programa decide cuándo pedir datos y se detiene hasta que presionas Enter.

Windows Forms

Flujo por eventos

El usuario decide el orden: puede escribir, hacer clic o cerrar la ventana en cualquier momento. Tu código espera y reacciona.

Dato histórico. WinForms apareció en 2002 con .NET Framework 1.0. Hoy existen WPF, MAUI y Blazor, pero WinForms sigue siendo muy usado para aprender programación orientada a objetos y eventos, porque muestra con claridad cómo se comunican la interfaz y tu código.

2. Anatomía de un proyecto

Al crear una Aplicación de Windows Forms en Visual Studio verás varios archivos. Cada uno tiene una función distinta:

Program.cs

Punto de entrada

Contiene Main(). Prepara la configuración visual y abre la ventana principal.

Form1.cs

Tu código

Es una partial class que hereda de Form. Aquí escribes tus eventos y tu lógica.

Form1.Designer.cs

Código del diseñador

Visual Studio lo genera cuando arrastras controles. Contiene InitializeComponent(). Evita editarlo a mano al inicio.

Form1.resx

Recursos

Archivo XML con imágenes, íconos y textos que usa el formulario.

// Program.cs (.NET 8)
static class Program
{
    [STAThread]
    static void Main()
    {
        ApplicationConfiguration.Initialize();  // estilos visuales y DPI
        Application.Run(new Form1());          // abre la ventana y el bucle de mensajes
    }
}

3. Programación guiada por eventos

Piensa en el timbre de una casa. No abres la puerta cada segundo por si acaso: esperas. Cuando alguien toca (evento), ejecutas una acción (manejador). En WinForms tu código permanece inactivo hasta que el usuario hace algo, y entonces Windows llama al manejador correspondiente.

private void btnSaludar_Click(object sender, EventArgs e)
{
    string nombre = txtNombre.Text;               // leer el TextBox
    lblMensaje.Text = $"Hola {nombre}, bienvenido";   // escribir en un Label
    MessageBox.Show("Perfil cargado", "Aviso");   // ventana emergente
}
object sender

Quién lo disparó

Es el control que generó el evento. Si varios botones comparten un manejador, ((Button)sender).Text te dice cuál se presionó.

EventArgs e

Datos del evento

Trae información extra. En eventos de ratón (MouseEventArgs) incluye la posición; en teclado (KeyEventArgs) la tecla pulsada.

4. Ciclo de vida de un formulario

Un formulario se crea, se muestra, se usa y se cierra. Saber en qué momento escribir tu código evita errores como NullReferenceException.

  1. ConstructorLlama a InitializeComponent(). Los controles existen en memoria, pero no se ven.
  2. LoadAntes de mostrarse. Úsalo para llenar listas e inicializar valores.
  3. ShownLa ventana ya es visible. Útil para dar foco a un campo.
  4. FormClosingEl usuario cierra la ventana. Puedes cancelar con e.Cancel = true.
  5. FormClosedLa ventana se cerró. Libera recursos que hayas abierto.

5. Galería de controles

Los controles son los objetos visuales que colocas en el formulario. Cada uno tiene propiedades (su aspecto y datos), métodos y eventos. Aquí tienes los 15 más usados: interactúa con cada demo y mira debajo qué evento de C# se dispararía. El recuadro de color es el prefijo recomendado para nombrarlo.

Cómo agregarlos en Visual Studio. Abre el Cuadro de herramientas (Ctrl+Alt+X), arrastra el control al formulario, ajusta sus propiedades con F4 y haz doble clic para generar su manejador de evento principal.

7. Cuatro errores frecuentes

Nombres por defecto

button1 y textBox1 vuelven ilegible tu código. Usa btnGuardar, txtNombre.

Olvidar que Text es string

Aunque escriban 25, es texto. Convierte con int.Parse(txtEdad.Text) o, mejor, int.TryParse para evitar excepciones.

MessageBox dentro de un bucle

Mostrar mil ventanas obliga a dar mil clics. Acumula el resultado y muéstralo una sola vez en un Label.

Thread.Sleep en la interfaz

Congela la ventana ("No responde"). Usa await Task.Delay(5000) en un método async.

Regla de oro. No edites Form1.Designer.cs a mano mientras aprendes: un cambio erróneo puede dañar el diseñador visual.
